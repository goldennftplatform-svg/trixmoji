1. Why these rules exist (full explanation)

Pond-style ecosystems often reward swap activity (counts, boost, mining offset, leaderboards, drops). That is fine when people make real, intentional swaps. It breaks when:

  • Everyone farms the same loophole (e.g. “old rails still open”) and dilutes rewards.
  • Bots and multi-wallet fleets spam dust loops faster than humans can trade.
  • Unofficial frontends appear (“connected to old rails,” mirrors, “Pond Scum boost tools”) and become phishing magnets.
  • Wash swaps burn gas for fake volume while looking like “healthy activity.”
  • Side rails get slammed shut after a rush — late farmers pay fees for nothing; early spam already hurt the culture.

Community rules cannot rewrite smart contracts. They can set culture: what we celebrate, what we refuse to amplify, and how mods protect people who just want to swap safely.

Design choice: open trading for everyone on regular Jupiter; old rails on DOSWAPZ limited to wallets with an activated Pond0x mining rig (list from Dune, stored server-side), plus safety caps (no continuous auto, max 5/session). Social rules + technical gate. We do not control Pond0x.com or the base chain.

3. Scope (Pond protocol wallets only)

  • These norms apply to Pond protocol wallets and Pond-related swap talk / activity in community spaces that adopt this doc.
  • Off-protocol farming, unknown boost tools, and non-Pond score games are not “how we do it here.”
  • Trade freely. Farm carefully. Don’t wreck the pond for everyone.
  • If official Pond documentation or protocol operators publish different rules, their rules win for protocol behavior. This doc governs community conduct.

4. Core principles

  1. Swaps are for using the protocol — not only for spamming a counter.
  2. One human, fair share — multi-wallet bot farms are against community spirit.
  3. Safety over FOMO — non-official links are hostile until proven otherwise.
  4. Don’t externalize costs — your farm should not dilute or endanger everyone else.
  5. Rules > loopholes — if a back door helps you and hurts the pond, do not normalize it.

5. Wallet rules

DO

  • Use a dedicated Pond / degen wallet for protocol activity when possible; keep long-term bags separate.
  • Connect that wallet only to official Pond surfaces the community recognizes.
  • Prefer normal, intentional swaps (size you actually meant to trade).
  • Reject wrong domains, surprise approvals, and weird routes — walk away.
  • Revoke junk approvals you no longer need (trusted revoke tools only, on your own schedule).

DON’T

  • Connect Pond wallets to random “old rails,” mirrors, or “secret boost” sites.
  • Sign unlimited or blind approvals “just to farm.”
  • Run bot fleets / script farms on Pond wallets to spam swap counts.
  • Share seed phrases, “support” DMs, or “sync wallet” links. Never.

6. Good swapping vs bad swapping

Encouraged

  • Swapping because you want the asset, liquidity, or normal protocol use.
  • A reasonable, human number of swaps.
  • Helping others swap safely (official links only).
  • Calling out drains, fakes, and farm spam without brigading.

Against community rules

  • Dust loops and pure wash cycles whose only goal is count / boost.
  • Coordinated multi-wallet rings funded to game rewards.
  • Teaching “spam old rails before they close” as the main strategy.
  • Guilt-tripping people into connecting sketchy UIs “or you’ll miss out.”
Community standard: if the swap only makes sense as a farm exploit and not as a trade, do not socialize it as the meta.

7. Safety (non-negotiable)

  1. Official Pond only for anything that needs your Pond wallet.
  2. No seed in chat. Ever.
  3. No “support” that needs your wallet, seed, or screen share of seed.
  4. If official swaps are down — wait. Do not “fix” with unknown rails.
  5. Loss limit = gas + what you meant to trade — not your whole bag on a farm.
  6. Assume side / old rails can die or stop counting — do not build identity on them.

8. Fair-share honor system

Because this is rules only (not code), enforcement is social + mod-side:

  • Aim for human-scale activity on wallets you actually use.
  • Do not treat thousands of wash swaps as an achievement.
  • If rewards feel share-based, leave room — pure extraction culture kills the pond.
  • Teach new people: safe swap first, farm second (or never).

Not a legal contract between members — a social contract so the place stays usable.

How access is checked (locked down)

On connect (and again before swap / auto), the client calls:

GET /api/pond-community?wallet={SOLANA_PUBKEY}

Default mode rigs_only: the backend looks up the wallet in the activated Pond0x rig database (populated from Dune “activated rigs” via POST /api/pond-rigs-sync). No dossier loophole.

Allowed if:

  • Wallet is on the activated-rigs list (Dune → store), or
  • Wallet is on operator POND_COMMUNITY_ALLOWLIST

Denied if: not on the list, on blocklist, or the rig DB is empty (fail closed until sync).

Optional modes: POND_COMMUNITY_MODE=hybrid (rig OR legacy signals) or signals (legacy only).

17. API, env vars, and operator notes

Public API

  • GET /api/pond-community?wallet=… — gate decision (checks activated-rig DB)
  • GET /api/pond-rigs-sync — DB status (count, updatedAt, source)
  • POST /api/pond-rigs-sync — pull Dune (auth required) or POST { "wallets": [] }
  • GET /api/pond-dossier?wallet=… — dossier proxy
  • GET /api/pond-mining?wallet=… — mining/rig proxy

Netlify env (operators — required for live Dune lock)

  • DUNE_API_KEY — Dune API key
  • DUNE_POND_RIG_QUERY_ID — Dune query id for activated rigs (e.g. dashboard rig activation query)
  • POND_RIGS_SYNC_SECRET — secret for POST sync
  • KV_REST_API_URL + KV_REST_API_TOKEN — recommended durable store (else Netlify Blobs)
  • POND_COMMUNITY_MODE — default rigs_only
  • POND_COMMUNITY_ALLOWLIST / BLOCKLIST — overrides

Sync: POST /api/pond-rigs-sync with Authorization: Bearer $POND_RIGS_SYNC_SECRET. Also scheduled every 6 hours on Netlify when env is set.

Client config (reference)

assets/js/config/pond-config.js — communityProxy, oldRailsAutoMax, oldRailsAutoMinWaitSec, jupiterSwapPath. Gate enforcement in assets/js/pond/dossier-swap.js stays always-on for old rails.

Product intent: safest for everyone + the site — open Jupiter for normal users; old rails only for wallets with an activated Pond0x rig (Dune list in our DB); no continuous farm loops; never require seeds; auto-disconnect after old-rails txs.

Operator first-run checklist

  1. Set Netlify env: DUNE_API_KEY, DUNE_POND_RIG_QUERY_ID, POND_RIGS_SYNC_SECRET, and ideally KV credentials.
  2. POST /api/pond-rigs-sync with Bearer secret (or wait for 6h schedule).
  3. Confirm GET /api/pond-rigs-sync shows count > 0.
  4. Test: blank wallet → locked; known activated-rig wallet → unlocked on Pond Scum.
  5. Confirm regular Jupiter still works for any Solana wallet.

// 01 · DIBZI.AI NAMES FOR CONTEXT

SOURCE · dibzi.ai/about · SHIPPED BUNDLE index-D2Sy9wRz.js · /api/names

A name is the asset. Resolution is the yearly record.

Site line: "Claim your name." The about page calls it a proposed onchain namespace for AI context. A name can point at a prompt, a reference set, a skill, or an encrypted file. Only the current owner can update the record. Their example shape is resolve("noir-grade") to owner, kind, digest, content, and reference.

WHAT THE ABOUT PAGE SAYS THE PIECES ARE

  • The name itself is a Metaplex Core asset on Solana. It stays in the wallet until someone transfers it. Ownership has no annual renewal.
  • Resolution is a separate record. It links the name to content and renews yearly. Renewal keeps resolution active. It does not keep ownership. If it expires, resolution pauses until someone renews.
  • Renewal on the name screen is 0.1 SOL per year.
  • You attach a description and a reference to an image, video, text, or Markdown file. The file can be public, or encrypted in the browser before it goes to IPFS.
  • The Solana program checks current ownership before a record update. The record publishes a SHA-256 digest so an integrator can compare the file they fetched with the committed hash.
  • Onchain state proves the owner and the digest. The resolver and the storage service still have to deliver the record and the file.
  • The registry publishes the reference, type, digest, description, and owner. The site says to share the access key only with services you trust.
  • Names can point at a word, a prompt fragment, or a whole template. An outside app could stitch those into a workflow and meter them. The about page says DIBZI does not commit to building that metering.
  • The about page names these uses: system prompts, agent skills, style references, character guides, model presets, datasets.
  • Builders are told to resolve a name, check the digest, and pull content from the resolver and manifest endpoints. Each app decides whether it honors a DIBZI name.

// MORPH · ONE-TIME ARTWORK · 2 OCT 2026

The shipped client is index-DC-kanY1.js. /api/config returns morphEnabled true, on program 3VQDLcMiUrqLHXhkinwj9AW9h5BHdqYkv4AY2cyTv7gS. The owner of a settled name that has not been morphed gets one button: MORPH ARTWORK · 0.1 SOL. The click rolls a style in the browser with Math.floor(Math.random()*3) and sends that style on the same wallet path as a bid, a buy, or a renewal. There is no style picker.

The dialog copy is "One-time 0.1 SOL immutable." After the wallet confirms, the success panel says YOU MORPHED IT and "Artwork morph activated." The name row then stores morphed, morphedAt, and morphStyle. The button is not offered again on that name. The activity feed labels the event MORPH. The admin panel has a MORPH REVENUE line, and a program upgrade that includes the feature prints ONE-TIME MORPH · 0.1 SOL.

A morphed name drops the type palette. The letters are drawn on a square canvas in Helvetica, forced to uppercase, and each vertical slice of a letter is scaled by a moving sine, so the word breathes. A spiral stroke in the corner is labeled Morphed. prefers-reduced-motion freezes the warp. Three styles are stored:
